# UNT0043 Possible typo in conditional compilation symbol

Mistyped conditional compilation symbols in `#if` and `#elif` directives are treated as undefined, so the affected branch can be compiled or skipped unexpectedly without a compiler error.

## Examples of patterns that are flagged by this analyzer

```csharp
#if UNITY_EDITOR || UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX || UNITTY_STANDALONE_OSX
    InitializeServiceLocator();
#endif
```

If the project defines `UNITY_STANDALONE_OSX` and no other symbol is an equally plausible correction, `UNITTY_STANDALONE_OSX` is reported as a likely typo. The analyzer gets the currently enabled symbols from Roslyn's parse options for the project; it does not maintain a catalog of Unity platform symbols.

The same applies to custom project symbols:

```csharp
#if FEATURE_RELEAS
    EnableReleaseFeature();
#endif
```

If the project defines `FEATURE_RELEASE`, this is reported as a likely typo.

## Avoiding false positives

An undefined symbol can be intentional: its code may target another platform, Unity version, or optional feature. The analyzer only reports an undefined symbol when exactly one enabled project symbol differs by a single insertion, deletion, substitution, or adjacent transposition. Symbols shorter than three characters and symbols declared with a local `#define` are not reported.

Numeric components must remain unchanged. For example, `FEATURE_1` is not corrected to `FEATURE_2` or `FEATURE_12`. Splitting or merging numeric components is also excluded.

Well-formed Unity version symbols are never reported, regardless of whether they are enabled in the current project:

- `UNITY_X`
- `UNITY_X_Y`
- `UNITY_X_Y_Z`
- `UNITY_X_Y_OR_NEWER`

Here, `X`, `Y`, and `Z` are numeric components. For example, these conditions are intentional even in a Unity 6.3 project targeting Windows:

```csharp
#if UNITY_6000_5_OR_NEWER
    UseNewerUnityApi();
#endif

#if UNITY_PS4 || UNITY_PS5
    UsePlayStationFeatures();
#endif
```

The analyzer does not change version numbers or suggest `UNITY_64` for `UNITY_PS4`. Spelling errors such as `UNITY_EDTIOR` or `UNITY_6000_3_OR_NEWRE` can still be reported if the intended symbol is enabled and the correction is unambiguous.

This is a conservative heuristic, not validation of all possible symbols. It can miss typos for inactive platforms or optional features, and similarly named optional symbols can still produce false positives. Review the intended condition before applying a fix.

## Solution

Use the intended symbol name:

```csharp
#if UNITY_EDITOR || UNITY_STANDALONE_WIN || UNITY_STANDALONE_LINUX || UNITY_STANDALONE_OSX
    InitializeServiceLocator();
#endif
```

A code fix is offered for this diagnostic to replace the mistyped symbol with the suggested project-level symbol.
